# BOM 版本与关联逻辑说明

## 1. 数据模型要点

- **BOM 行**：每行表示「主件(material_id) + 版本(version)」下的一个子件(component_id)及其用量等。
- **版本归属**：`version` 属于**主件**，即同一 `(material_id, version)` 下的所有行构成该主件在该版本下的 BOM。
- **子件无版本字段**：BOM 行中不存储「子件用哪一版 BOM」；子件（半成品）自己的 BOM 由其自身的 `(material_id, version)` 决定，通过 hierarchy 接口按默认/最新版本展开。

## 2. 版本解析（列表 / 设计器一致）

- **未指定 version** 时：优先使用该物料的**默认版本**（`is_default=True`），若无则使用**最新版本**。
- 设计器 hierarchy、列表页展示均按上述规则解析版本，保证两边看到的子件一致。

## 3. 升版（Revise / 另存为新版本）

- **revise**：仅针对**当前主件**复制一份新版本（新 `version`），只复制该主件的 BOM 行（其直接子件列表），**不**为子件（半成品）创建新版本。
- **设计器「另存为新版本」**：只提交**根级直接子件**到 batch_import，不提交整棵树的递归结构，从而只对当前编辑的主件升版，未改动的半成品保持原版本。

## 4. 批量导入（batch_import）与版本

- 请求中的 `items` 按 `parent_code` 分组，每个 `parent_id` 下按 `target_version` 做**全量替换**（先软删同主件同版本，再插入新行）。
- 若请求里包含多个主件（多个 parent_code），则每个主件都会按同一 `target_version` 被替换；因此「另存为新版本」时前端应只传**当前主件**的直接子件，避免半成品被误写为新版本。

## 5. 最佳实践小结

| 场景           | 行为说明 |
|----------------|----------|
| 列表默认展示   | 主件用默认版本或最新版本，子件展开时用其默认/最新版本。 |
| 设计器打开     | 与列表一致：未传 version 时用主件默认版本或最新版本。 |
| 草稿保存       | 可提交整树（多级），当前主件及展开的半成品按各自当前版本全量替换。 |
| 另存为新版本   | 仅提交根级直接子件，只对当前主件升版；半成品不升版。 |
| 子件 BOM 修改   | 应进入该子件（半成品）的 BOM 设计器单独编辑与升版。 |
