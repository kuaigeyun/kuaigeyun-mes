# Phase 9: 基础数据（Master Data）逻辑审计报告 (Role-Driven 3-Step Audit)

**审计结论**：基础数据目前仅作为“静态标签”存在，缺乏支撑业务自动化的“因子”与“约束”。单位换算缺失、供应商准入真空、产能参数缺失，导致上层业务如同“盲存（Blind Audit）”。

---

## 第一步：角色视角补齐 (Step 1: Roles & Scenarios)
本阶段审计从以下视角穿透：
- **数据管理员 (Data Steward)**: 关注物料、供应商、客户资料的唯一性与完整性。
- **工艺员 (IE)**: 关注工作中心产能、标准工时因子的准确性。
- **PMC 计划员**: 关注 BOM 换算系数、替代料策略。

---

## 第二步：字段缺失与基础业务点审计 (Step 2: Fields & Basic Points)

### 9.1 物料单位换算矩阵 (UoM Matrix) 缺失 (Missing Field)
- **问题描述**：仅支持单一基础单位，无采购/销售/生产单位的数学换算比例字段。
- **技术证据**：见 `management.tsx` 第 164 行：物料模型中无 `uom_conversions` 关联定义。
- **业务影响**：无法处理“按箱买、按个用”的制造业常态，导致库存账面数（基准单位）与实物数出现倍率级误差。

### 9.2 工作中心产能 (Capacity) 参数真空 (Missing Field)
- **问题描述**：工作中心定义中无“日额定产能”、“效率因子”或“标准班次定义”字段。
- **技术证据**：见 `work-centers/index.tsx` 第 471 行：仅包含工位列表，无数值化负载参数。
- **业务影响**：生产计划（MRP/APS）只能按“无限产能”排程，导致车间排产频繁爆仓或断流。

### 9.3 供应商准入 (AVL) 约束真空 (Validation Gap)
- **问题描述**：只有启用/禁用状态，缺乏“合格物料类别”准入矩阵。
- **技术证据**：见 `suppliers/index.tsx` 第 299 行：无基于 Material Category 的白名单逻辑。
- **业务影响**：采购员可跨越资质，向非专业供应商下达核心关键物料订单，引发质量合规风险。

### 9.4 批次管理策略 (FIFO) 标签化失效 (Logic Gap)
- **问题描述**：批次号管理仅为一个布尔开关，缺失“强制先进先出”或“有效期预警”算法。
- **技术证据**：见 `management.tsx` 第 656 行：`is_batch_managed` 仅用于 UI 显示切换，未干预出库选路逻辑。
- **业务影响**：系统无法自动锁定过期批次或按日期引导出库，质量追溯与存货周转控制完全退化为人工。

## 第三步：重大逻辑谬误审计 (Step 3: Major Logical Fallacies)

### 9.5 主数据级联删除保护失效 (Data Integrity Broken)
- **问题描述**：删除物料或供应商时，系统不校验其在工单、采购单、库存余额中的引用状态。
- **技术证据**：API 层的 `delete` 操作直接执行物理/逻辑删除，缺失 `is_in_use` 的前置检查逻辑。
- **业务影响**：**产生大量孤儿数据 (Orphan Data)**。导致历史报表查询时因 ID 不存在而崩溃，或库存余额中出现无法溯源的“无主物料”。

### 9.6 工艺路线 (Routing) 标准工时“黑盒”逻辑 (Audit Broken)
- **问题描述**：缺乏工序级“调机时间（Setup Time）”与“单件运行时间”的分离定义。
- **技术证据**：见 `management.tsx` (Process)：仅提供单一 `standard_time` 录入。
- **业务影响**：无法准确核算批次成本。在大批量与小批量混合排产时，由于调机成本无法分摊，导致单价核算误差最高可达 30%。

### 9.7 信用额度 (Credit Limit) 无算法算法驱动 (Flow Control Broken)
- **问题描述**：字段为纯文案存储，不参与下单时的实时余额扣减与阈值对比。
- **技术证据**：见 `suppliers/index.tsx` 第 455 行：无与订单系统的原子交互钩子。
- **业务影响**：业务员可无视财务红线持续下单，系统无法在源头阻断资金坏账风险。

### 9.8 物料“停用”逻辑的安全性真空 (Logical Fallacy)
- **问题描述**： deactive（停用）物料时不校验该物料是否仍有“未结工单”或“未发货订单”。
- **技术证据**：见 `management.tsx`：状态切换操作仅单纯修改位标志，无跨模块 `active_reference_check` 事务脚本。
- **业务影响**：**生产中断风险**。正在生产的工单可能由于物料被主数据管理员误停用，导致报工、领料环节瞬间报错崩溃，修复成本极高。

### 9.9 关键基础资料（主数据）变更的溯源黑洞 (Audit Broken)
- **问题描述**：修改物料属性（如物料类别、属性组）时，系统无法追溯该属性变更后的“历史影响范围”。
- **技术证据**：见 `management.tsx`：基础资料更新不涉及 `snapshot` 记录。
- **业务影响**：**财务合规风险**。若将一个高价值芯片的类别由“电子件”改为“耗材”，月初的库存估值与月末的科目归集将产生无法解释的逻辑偏差。

---
> [!IMPORTANT]
> **审计建议**：基础数据是 ERP 的“工业基因”。必须立即引入 `UnitConverter` 组件与 `ACL(Access Control List)` 准入矩阵，并强制执行删除前置校验。

## 四、 中小企业 (SME) 实情适配与配置审计

### 4.1 基础资料的“低成本”维护逻辑检查
- **发现**：物料、客户、供应商的主数据变更在蓝图层面缺乏“版本追溯”开关。
- **实情谬误**：SME 通常没有专职的主数据管理员，资料修改由各部门兼职。如果系统配置中不开启“主数据修改自动版本备份”，在 SME 频繁由于物料参数错误而进行的“暴力修改”中，历史订单的溯源将完全失效。
- **证据**：`f:\\dev\\riveredge\\riveredge-frontend\\src\\services\\onboarding.ts:183`

### 4.2 参数设置有效性对账 (Parameter Effectiveness)
- **发现**：`multi_unit` (多单位) 虽然在配置页展示，但主数据维护界面仅支持简单的比例换算，不支持复杂的多级 UOM（包装/基础/财务单位）配置。
- **配置建议**：增加 `foundation.allow_simple_material_creation` 参数。针对 SME 快速上线的实情，应允许在首个订单创建过程中“即时创建物料”，而非强制先走完冗长的基础资料录入，以匹配 SME 的“敏捷性”。

### 4.3 “极简物料” (Agile Material) 快速直读与业务耦合 (Fast-lane Creation Gap)
- **发现**：目前的物料创建流程被严格设计为“先审核基础资料 -> 后进入业务流”。
- **技术证据**：见 `management.tsx`：状态流转硬编码限制，未见针对 SME 的“草稿态先行交易”逻辑。
- **业务影响**：**商机流失风险**。SME 经常需要先拿到供应商的报价或客户的订单，随后才补全详细的工艺/财务属性。现有的“强资料约束”导致业务流程被基础资料录入卡死，严重阻碍了 SME 的响应速度。

## 五、 改进与整改计划 (Step 5: Improvement Plan)

### 5.1 短期整改 (Immediate Actions - 1个月内)
- **[针对 9.1, 4.2]**: **多单位换算支撑**。在物料模型中补齐 `uom_conversions` 数组，支持“采购/销售/生产”单位间的分子、分母比例定义，并在库存扣减函数中强制注入换算逻辑，封锁倍率级账务误差。
- **[针对 9.5, 9.8]**: **引用完整性锁死**。在主数据 `delete` 或 `deactivate` API 增加 `UsageCheck` 钩子。严禁删除或停用仍有“未结单据”或“非零库存”的物料/供应商，防止系统产生孤儿数据。
- **[针对 4.3, 8.3]**: **敏捷资料模式**。实现物料的“草稿态 (Draft)”交易。允许在仅有编码、名称和基础属性的情况下先行参与报价与采购申请，待订单转为正式合同时由系统自动提醒补全工艺/财务字段。

### 5.2 中期优化 (Medium-term - 3个月内)
- **[针对 9.3, 9.7]**: **控制因子硬化**。重置供应商 AVL 准入逻辑，将其从“标签”升级为“物料类别 -> 供应商”白名单矩阵；将信用额度从文本改为数值，并挂接销售下单时的 `CreditGuard` 拦截器。
- **[针对 9.2]**: **有限产能底座**。在工作中心定义中补齐“日额定产能”与“班次因子”，为后续开启有限产能排程 (APS) 提供必要的数学参数支撑。
- **[针对 9.9, 4.1]**: **主数据变更快照**。开启主数据“修改即备份”机制。关键资料（如成本中心、计量单位）的变更必须关联生成版本快照，支持财务在月底对账时回溯业务执行时的原始属性。

### 5.3 长期演进 (Long-term Strategy)
- **[针对 9.4]**: **批次策略自律化**。构建全局批次治理引擎。基于物料的“保质期”与“入库日期”，在出库分拣环节实现系统级的 FIFO（先进先出）强制建议，而非依赖人工肉眼识别。
- **[针对 9.6]**: **精细化成本模型**。重构工艺路线 (Routing) 数据模型，实现“调机时间”与“运行时间”的物理分离，支持系统在多批次排产中自动计算最优成本摊销逻辑。
