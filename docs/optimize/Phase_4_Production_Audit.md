# Phase 4: 生产与计划管理审计报告 (Role-Driven 3-Step Audit)

**审计结论**：生产模块目前处于“过程记录”阶段，而非“过程控制”阶段。缺乏对生产现场实物流动与数据流动的硬性强校验，存在严重的追溯链断裂、WIP（在制品）账实不符以及计划排产盲动风险。

---

## 第一步：角色视角补齐 (Step 1: Roles & Scenarios)
本阶段审计从以下视角穿透：
- **生产计划 / PMC (Planner/PMC)**: 关注 MRP 准确性、物料齐套看门狗 (Readiness Gate)。
- **计划排程岗位 (Scheduler)**: 关注有限产能 (Finite Capacity)、工序排队顺序。
- **生产派工岗位 (Dispatcher)**: 关注生产指令下达、派工状态穿透、优先级控制。
- **生产工人 (Worker)**: 关注工位 SOP 获取、报工真实性、上料防呆 (Poka-yoke)。

---

## 第二步：字段缺失与基础业务点审计 (Step 2: Fields & Basic Points)

### 4.1 工位 SOP 数字化映射字段缺失 (Worker Perspective)
- **问题描述**：工序表中无针对特定工位、特定版本的 SOP 文档直链。
- **技术证据**：见 `execution/index.tsx`：报工界面仅展示工单信息，无操作指引（SOP）挂载点。
- **业务影响**：生产工人无法实时获取最新工艺要求，导致错装、漏装风险高发，制造一致性极差。

### 4.2 产能负荷 (Capacity Load) 字段与机台匹配缺失 (Scheduler Perspective)
- **问题描述**：工单与排程系统内缺乏真实的机台/人员能力（Ability）字段。
- **技术证据**：见 `work-orders/index.tsx`：排程仅通过 `required_date` 排序，未见 `resource_load_index` 引用。
- **业务影响**：排产完全基于经验，系统无法拦截因机台故障或产能饱和导致的“死计划”。

### 4.3 齐套率 (Readiness Rate) 仅作为展示参数 (PMC Perspective)
- **问题描述**：工单详情显示的齐套率并不干预工单的“确认”或“下达”动作。
- **技术证据**：见 `work-orders/index.tsx:L185`：该字段仅为 UI 展示，并未在后端状态切换 API 中作为拦截位。
- **业务影响**：允许在物料缺失的情况下强行下达给车间，导致线边仓积压与频繁的停工待料。

### 4.4 派工指令单 (Dispatch Note) 独立化按钮缺失 (Dispatcher Perspective)
- **问题描述**：缺乏独立的、支持多阶段拆分的派工下达流程。
- **技术证据**：见 `work-orders/index.tsx`：目前直接由工单跳转至报工，无“指令下放-确认签收”的派工过程。
- **业务影响**：生产现场执行具有滞后性，派工员无法分批下达任务，管理粒度过粗。

## 第三步：重大逻辑谬误审计 (Step 3: Major Logical Fallacies)

### 1.1 节点工序跳步逻辑疲软 (Core Execution Logic Broken)
- **问题描述**：工序逻辑检查仅校验前序是否有“任意值”记录，而非“合格完工量”。
- **技术证据**：见 `reporting/index.tsx:L508-510`：`completed_quantity <= 0` 属于最低阈值校验，而非针对工单总量的容差校验。
- **业务影响**：允许前序仅仅报工 1 个即可开启后序 100 个的作业，导致不合格品或短缺件在生产线中“带病流转”。

### 1.2 物料绑定与报工逻辑由于 UI 逻辑解耦 (Traceability Broken)
- **问题描述**：上料（物料绑定）是可选动作，报工过程不强制关联组件消耗。
- **技术证据**：见 `reporting/index.tsx:L241`：调用报工 API 前无任何 `feeding_list` 完整性校验逻辑。
- **业务影响**：**质量追溯灾难**。成品产出记录可能完全缺失对应的原材料批次 ID，导致发生质量事故时无法找回问题原材料来源。

### 1.3 标准工时自动填充导致的“完美伪象” (OEE Audit Broken)
- **问题描述**：报工时自动按标准工时填充实际时间。
- **技术证据**：见 `reporting/index.tsx:L640-661`：`work_hours = standard_time * wo.quantity` 将理论值直接覆盖实测值。
- **业务影响**：掩盖现场效率异常。OEE 统计变为“恒定满分”，导致管理者无法发现真实的怠工或设备隐性损耗。

### 1.4 工单手工结案下的 WIP 物料泄漏 (WIP Inventory Leak)
- **问题描述**：工单手动结案不触发未消耗组件的自动退料或盘亏记录。
- **技术证据**：见 `work-orders/index.tsx:L178`：系统仅修改状态位，未联动库存冲回动作。
- **业务影响**：工单领出但未用的物料永久消失在“车间黑洞”中，导致库存账实严重不符。

### 4.5 MRP 需求重复计算与 BOM 路径冲突 (PMC Planning Logic Broken)
- **问题描述**：针对同一需求来源，多次计算可产生重合的采购建议，且存在版本选路错误。
- **技术证据**：见 `demand-computation/index.tsx`：缺少对已下推需求的全局占号校验。
- **业务影响**：导致重复采购或重复生产，产生巨额外溢库存积压风险。

### 4.16 物料“盲目超耗”拦截缺失 (Logical Fallacy)
- **问题描述**：报工环节的物料上料绑定（Material Binding）不校验 BOM 标称用量，允许工人无限度绑定物料。
- **技术证据**：见 `reporting/index.tsx` 第 709-720 行：`handleSubmitMaterialBinding` 仅单纯记录，无 `issued_vs_consumed` 余量控制。
- **业务影响**：**线边仓物料“人间蒸发”**。实际已超领 200% 物料用于补漏，但由于报工程序不拦截，仓库账面仍显示“有库存”，导致直到月底盘点才知道已经亏损数百万，完全丧失事中纠偏能力。

### 4.17 SOP 参数“阈值脱节”记录谬误 (Logical Fallacy)
- **问题描述**：系统仅收集 SOP 数据，不针对工艺要求的“上线/下限”进行即时硬阻断（Hard Stop）。
- **技术证据**：见 `reporting/index.tsx` 第 198-209 行：校验逻辑仅存在于“必填性”，而非“数值合理性校验”。
- **业务影响**：**质量批量报废风险**。如果工艺要求温度 80°C，工人输入 20°C 系统仍允许报工成功。这使得 SOP 收集沦为“数据填报作业”，而非真正的“工业自动化过程控制”。

### 4.18 “状态报工”导致的产出数据孤儿化 (Logical Fallacy)
- **问题描述**：按“状态”报工时，系统强行将产出数量定为 1（或 0），与实际生产批次（如 1000 个）完全脱节。
- **技术证据**：见 `reporting/index.tsx` 第 229-231 行：逻辑分支硬编码固定产出。
- **业务影响**：**WIP 核销断层**。前端报工显示“已完成”，但后台无法根据该信号核销对应工序的在制品余额，导致生产中心数据永远处于“账实不符”状态。

---
> [!IMPORTANT]
> **审计建议**：必须立即将“上料绑定”设为“报工确认”的前置硬门槛。针对工序流转，应引入基于“前序合格产出平摊”的数量联锁机制，封锁跳步绕过漏洞。

## 四、 中小企业 (SME) 实情适配与配置审计

### 4.1 业务蓝图逻辑检查 (Blueprint Integrity)
- **发现**：`production_plan` (生产计划) 在蓝图中作为独立节点存在。
- **实情谬误**：SME 往往是“以单定产”，直接从 SO 推到 WO，中途不需要正式的 `production_plan`。蓝图应允许“一键跳过计划”的直达配置。
- **证据**：`BusinessFlowConfig.tsx:124`

### 4.2 参数设置有效性对账 (Parameter Effectiveness)
- **发现**：`allow_production_without_material` 参数虽然存在于 configuration，但报工逻辑并未读取此开关。
- **配置建议**：中小制造业常见“先加工再入库”的情况，应增加 `production.quick_reporting_allow_post_material_binding` 开关，并确保该开关能真实改变 `reporting/index.tsx` 的验证逻辑。

### 4.3 工单“一向听”状态撤回逻辑缺失 (Order Reversal Gap)
- **发现**：工单一旦进入“已下达”或“执行中”状态，前端缺乏灵活的“撤回至草稿”或“冲销”按钮，仅有“终止”或“冻结”。
- **技术证据**：见 `work-orders/index.tsx`：搜索 `revoke` 或 `cancel_to_draft` 逻辑分支缺失。
- **业务影响**：**管理僵化风险**。SME 经常由于临时停电、换料或紧急单插入需撤回已下达的工单，目前系统仅能通过“终止”实现，导致单据序列号浪费且数据无法二次编辑。

### 4.4 生产投料的“批次锁”验证真空 (Batch Lock Gap)
- **发现**：领料单（Pick List）虽记录批次号，但在报工上料（Material Binding）环节不强制校验该批次是否与领料批次一致。
- **技术证据**：见 `material-binding/index.tsx`：验证逻辑仅针对 `material_id`，不具备跨单据的 `batch_id`联锁。
- **业务影响**：**追溯链假象风险**。工人可能拿着 A 批次的料报了 B 批次的上料，系统由于缺乏联锁而不报错。这对于需要严格追溯（如电子、食品）的 SME 来说是致命逻辑缺陷。

## 五、 改进与整改计划 (Step 5: Improvement Plan)

### 5.1 短期整改 (Immediate Actions - 1个月内)
- **[针对 1.2, 4.4]**: **投料合规联锁**。将“上料绑定”从报工的可选项升级为“必选项”。在上料阶段，后端必须实时校验 `batch_id` 是否属于该工单对应的 `pick_list` 实发批次，封锁批次挪用风险。
- **[针对 4.3]**: **灵活性恢复 (Order Reversal)**。在工单管理界面新增 `handleRevokeToDraft` 动作，允许在未产生实际报工前，将“已下达”工单撤回至“草稿”态，释放占用的单据号与锁定资源。
- **[针对 1.1]**: **工序流转硬约束**。重构报工校验 API，强制要求 `previous_op_qualified_qty >= current_op_reporting_qty`，严禁在无合格前序产出的情况下开启后序作业。

### 5.2 中期优化 (Medium-term - 3个月内)
- **[针对 1.3, 1.4, 4.18]**: **真实绩效与 WIP 核销**。移除“标准工时自动填充”逻辑，强制采集“实际开始/结束时间”；实现工单结案时的“自动余料冲回”逻辑，确保车间线边仓账实相符。
- **[针对 4.1, 4.17]**: **数字化工艺门禁 (SOP Gate)**。在报工界面集成 SOP 动态预览，并针对工艺参数（如温度、压力）设置“上下限拦截阈值”，数值越界时禁止报工提交，实现由“填报”向“控制”的转型。
- **[针对 4.2]**: **有限产能排产初探**。引入“工作中心 (WorkCenter) 每日额定工时”参数，排产时若总需求工时超过额定能力，系统应输出“产能赤字预警”而非盲目排入计划。

### 5.3 长期演进 (Long-term Strategy)
- **[针对 4.5]**: **大规模算力重构 (MRP Offload)**。将 MRP 需求运算与 BOM 递归校验从前端 JS 线程完全迁移至后端 Celery 异步队列，解决大批量订单场景下的浏览器死机与重复计算问题。
- **[针对 1.1, 4.18]**: **全局 WIP 透明化**。打通从原材料入库 -> 工序拨付 -> 产成品入库的全程资产价值链，实现单件/单批次的实时制造成本滚动累加。
