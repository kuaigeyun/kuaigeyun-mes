### 重复需求归并说明

各部门站在自身角度提出了大量重叠需求，归并后有三大重复主题：

1. **委托实验**：实验室（#2/#3）、研发电子（#13）、研发结构（#28/#29）、研发项目（#39/#45）共 4 个部门提出 7 次，本质是同一个「实验委托单」流程。
2. **受控文件（上传-审批-版本-下载权限）**：体系（#1）、PE（#9）、研发电子（#14-#20）、研发结构（#21-#26）、研发项目（#40/#42/#44/#49/#50）共 5 个部门提出 20+ 次，全部指向同一套文档管理能力。
3. **变更流程**：体系、PE、研发电子（#20）、研发结构（#26）、研发项目（#48）重复提出，可统一由已有的工程变更 ECN 承载，补充部门填写节点即可。

## 三、开发计划

### 3.1 优先级排序原则

- **P0**：多部门重复提出、覆盖需求条目最多、其余需求依赖其基础能力
- **P1**：单一部门核心业务闭环、有明确管理痛点（预警/考核）
- **P2**：可复用 P0/P1 成果快速交付、或使用频次较低的补充能力

| 优先级 | 需求组 | 覆盖条目数 | 理由 |
|---|---|---|---|
| P0 | 受控文件管理（DMS） | 20+ 条 | 5 个部门重复提出，覆盖面最大；生产软件发放、校准证书归档等均依赖其基础能力 |
| P0 | 实验室委托实验（LIMS） | 7 条 | 4 个部门重复提出，当前完全空白 |
| P1 | 供应商档案与准入管理 | 5 条 | 采购、IQC 两部门核心诉求，涉及合规（合同/环保协议）与预警 |
| P1 | 审批/会签类业务单据 | 5 条 | 有审批中心基础，补自定义表单与超期预警即可覆盖多张单据 |
| P1 | 供应商品质考核与报表 | 3 条 | 有检验统计基础，需新增扣分规则与月度排名引擎 |
| P2 | 生产软件与烧录工具发放 | 3 条 | 复用 DMS 的版本与权限能力，扩展发放/签收记录 |
| P2 | 年度实验计划管理 | 2 条 | 复用 LIMS 的实验执行与报告能力，扩展计划维度 |
| P2 | 试流单（试产流程） | 1 条 | 有试产阶段门基础，补工序级流转 |
| P2 | 设备/仪器校准证书管理 | 1 条 | 挂接现有设备检定模块附件即可 |

### 3.2 阶段划分

#### 第一阶段：平台基础能力（P0）

**1. 受控文件管理（DMS）** — 覆盖 #1、#9、#14-#24、#26、#40、#42、#44、#49、#50

- [ ] 文档库模型：文档分类目录树（按产品型号 + 版本号）、文档元数据（编制人/版本/状态）
- [ ] 文档生命周期状态机：草稿 → 审核 → 批准 → 发放 → 变更 → 撤销/作废
- [ ] 接入核心审批中心：编制完成后流程通报节点负责人审核批准
- [ ] 版本管理：历史版本保存与追溯、版本对比查看
- [ ] 借用/归还登记：借用人、借用时间、归还人、归还时间
- [ ] 文件级下载权限控制（区别于查看权限，按角色/人员授权）
- [ ] 新旧料号关联：部品/整机料号变更后可链接老料号下的测试报告（#18）
- [ ] 变更文件模板套用与签核（#20）
- [ ] 与现有图纸管理、SOP、研发项目交付物打通（避免双入口）

**2. 实验室委托实验（LIMS）** — 覆盖 #2、#3、#13、#28、#29、#39、#45

- [ ] 实验委托单：IQC 委托 / 研发委托 / 委外试验三类单据
- [ ] 委托单字段：试验名称、试验原由、样品信息、开始时间、预计完成日期
- [ ] 委外试验价格节点：研发填写试验内容，价格由指定人或采购填写、审核、批准（#45）
- [ ] 实验执行：实验室接单、排期、录入结果、上传实验报告
- [ ] 完成后邮件通知申请人（复用消息中心邮件通道，#13）
- [ ] 样品检验单（#28）；材料/整机例试单多人协作编辑（#39）
- [ ] 权限：按 manifest 声明 `{app}:{module}:{action}` 权限码并同步

#### 第二阶段：供应商管理与审批扩展（P1）

**3. 供应商档案与准入管理** — 覆盖 #7、#30、#35、#37、#38

- [ ] 供应商档案扩展：合同、质量协议、环保协议登记（签署状态、有效期、盖章扫描件上传）
- [ ] 未签 / 超期自动预警（#7）；环保资料到期前 30 天提醒（#35）
- [ ] 供应商审核评价：评价表上传汇总、审核批准流程，不合格需整改后方可准入（#30）

**4. 审批/会签类业务单据** — 覆盖 #27、#41、#43、#46、#48

- [ ] 自定义审批表单：物料申请单、技术工作联系单、确认书等（基于核心审批中心）
- [ ] 审批超期自动预警（未签或超期提示，#27）
- [ ] 领料单多部门会签：采购、销售、计划会签后仓库配料（#46，扩展现有生产领料单）
- [ ] 变更单部门填写节点：库存统计、库存处理、在制品处理方式等（#48，扩展现有 ECN）

**5. 供应商品质考核与报表** — 覆盖 #33、#34、#36

- [ ] 扣分规则配置：基于 IQC 抽检不良数据按规则自动扣分
- [ ] 月度品质报表：自动汇总评分、供方排名、考核结果；年度趋势图
- [ ] 上线不良数据：供应商维度的上线不良率排名、不良项目汇总分布

#### 第三阶段：场景化扩展（P2）

**6. 生产软件与烧录工具发放** — 覆盖 #10、#16、#17（复用 DMS）

- [ ] 产测文件库：烧录工具/烧录软件/镭雕软件/AOI 文件/标签模板分类，型号+版本管理
- [ ] 发放/接收双向记录：发放人、发放时间、接收人、接收时间
- [ ] 下载权限控制（复用 DMS 文件级权限）

**7. 年度实验计划管理** — 覆盖 #4、#5（复用 LIMS）

- [ ] 年度例式实验计划、年度库存验证计划台账
- [ ] 计划 → 实验执行 → 结果报告关联，执行进度跟踪

**8. 试流单** — 覆盖 #47

- [ ] 研发发起试流申请（填写试流内容）
- [ ] 按工艺路线逐工序流转，工序负责人填写试流结果
- [ ] 各部门负责人填写试流结论，完成后关闭存档可查
- [ ] 与快研发试产阶段门联动

**9. 设备/仪器校准证书管理** — 覆盖 #6

- [ ] 设备检定单挂接校准证书附件（上传/查看/下载）
- [ ] 实验室确认结果回传字段

### 3.3 依赖关系

```
受控文件管理（DMS）─┬─→ 生产软件与烧录工具发放（复用版本/权限）
                    ├─→ 设备校准证书管理（复用文件归档）
                    └─→ 供应商协议档案（复用文件归档与到期提醒）

实验室委托实验（LIMS）──→ 年度实验计划管理（复用实验执行/报告）

核心审批中心（已有）─┬─→ DMS 审批发放流
                    ├─→ 自定义审批表单 / 超期预警
                    └─→ 供应商准入审批

来料检验/质量异常（已有）──→ 供应商扣分规则 → 月度品质报表排名
```

### 3.4 通用技术要求

- **权限**：所有新模块须在应用 `manifest.json` 声明 `{app}:{module}:{action}` 权限码并完成权限同步；后端显式 `require_permission_codes`，前端使用 `useResourcePermissions` 门控；提交前通过 `scan_permission_bypass.py --fail-on high`。
- **审批**：统一复用核心审批中心（ApprovalInstance），不得在应用内自建审批流。
- **文件**：统一使用 core_files 文件服务，不得另建文件存储路径。
- **通知**：预警与邮件通知统一走消息中心（站内信 + 邮件通道）。
- **菜单**：新菜单顺序仅在后端 manifest `menu_config` 的 `sort_order` 声明，前端不做二次排序。

### 4.4 报价与工期说明

1. 报价包含：需求细化、开发、自测、联调、部署上线、操作培训（1 次）及上线后 **1 个月免费缺陷修复**。
2. 报价不包含：验收后新增的需求变更（另行评估报价）、差旅费用、第三方软硬件采购费用。
3. 工期自合同签订且客户提供必要资料（组织架构、审批路线、表单模板、扣分规则等）之日起计算；客户确认环节（原型评审、里程碑验收）单次超过 3 个工作日未反馈的，工期顺延。
4. 三个阶段按依赖关系顺序交付，每阶段完成即可上线试用，无需等待整体完工。
5. 各审批路线、表单模板、预警天数、扣分规则均按通用配置化方案实现，后续调整无需二次开发。
