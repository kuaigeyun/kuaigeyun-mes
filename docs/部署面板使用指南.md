# RiverEdge 部署面板使用指南

部署面板用于在空白 Windows/Linux 环境下图形化准备 RiverEdge 部署所需的环境（Node、Python、PostgreSQL 等），并完成配置与一键启动。单二进制、零运行时依赖，双击运行后访问 `http://127.0.0.1:8300` 即可使用。

---

## 前置准备

### 项目目录结构

将编译好的面板二进制放入 RiverEdge 项目目录：

```
riveredge/
├── riveredge-panel/
│   ├── riveredge-panel-linux-amd64   # Linux
│   ├── riveredge-panel-windows-amd64.exe  # Windows
│   └── Launch.prod.sh
├── riveredge-backend/
├── riveredge-frontend/
├── riveredge-mobile/
└── Launch.dev.sh
```

### 首次运行

1. **Linux**：`./riveredge-panel/riveredge-panel-linux-amd64` 或 `sudo ./riveredge-panel/riveredge-panel-linux-amd64`（使用一键安装时建议 sudo）
2. **Windows**：双击 `riveredge-panel-windows-amd64.exe` 或命令行运行
3. 浏览器访问 http://127.0.0.1:8300
4. 首次使用需设置 Master 密码，后续访问需输入此密码

---

## 第一步：环境检测

检测您的电脑是否已安装运行 RiverEdge 所需的软件。

### 检测项说明

| 组件 | 说明 | 必需 |
|------|------|------|
| Node.js 22+ | 前端运行环境 | 必需 |
| Python 3.12 | 后端运行环境 | 必需 |
| UV | Python 包管理 | 必需 |
| npm | 前端包管理 | 必需 |
| PostgreSQL 15+ | 数据库 | 必需 |
| Caddy | 生产反向代理 | 建议 |

### 操作说明

- **全部通过**：点击「全部通过，填写配置 →」进入第三步
- **有未安装项**：点击「有未安装项，去安装 →」进入第二步
- **重新检测**：安装完成后点击「重新检测」刷新状态

---

## 第二步：安装缺失组件

根据检测结果，安装未满足的组件。

### Windows

复制下方命令，在 **以管理员身份运行** 的终端中执行：
- 右键「开始」→ Windows Terminal（管理员）或 CMD（管理员）

### Linux / Ubuntu

- **Ubuntu 22/24**：支持「一键安装」，可直接点击按钮安装
- 其他发行版：复制命令到终端执行

### Ubuntu 22 测试提示

面板已在 **Ubuntu 22.04** 上完整测试，推荐作为生产部署环境：

- **一键安装**：支持 Node.js、Python、UV、PostgreSQL、Caddy 等组件的一键安装
- **sudo 权限**：使用一键安装时需 `sudo`，建议以 `sudo ./riveredge-panel` 运行面板，否则安装时可能提示输入密码
- **国内镜像**：国外源（astral.sh、cloudsmith、GitHub）访问较慢时，可勾选「使用国内镜像」加速安装
- **生产脚本**：`Launch.prod.sh` 针对 Ubuntu 22.04 优化，4GB 内存环境可运行

### 安装完成后

点击「已安装完成，去配置 →」进入第三步。若所有组件已安装，可直接点击顶部进度条「填写配置」跳转。

---

## 第三步：填写配置

填写数据库等连接信息。

### 部署方式

- **本机数据库**：数据库安装在本机，主机填 `localhost`
- **远程数据库**：使用云 RDS 等，填写实例地址

选择「远程数据库」时，会显示安全组提醒：生产环境仅需对外放通 Caddy 端口 8080（或 80/443）。

### 数据库配置

- 主机、端口（默认 5432）、用户、密码、数据库名
- 点击「测试连通性」验证连接
- 数据库不存在时会自动创建

### 应用配置

- 平台超级管理员密码（首次登录用）
- Git 仓库地址、部署分支
- Node 构建内存（MB）

### Caddy 反向代理（生产环境）

- 域名（可选，留空则用 localhost）
- 监听端口（默认 8080）
- 启用 Let's Encrypt 自动 HTTPS（需填写域名且 80 端口可从公网访问）

### 云服务器 PostgreSQL 操作提示

若使用远程数据库，可展开查看在云服务器上设置 postgres 密码、开启远程访问的命令。

### 保存配置

点击「保存配置」后，「去部署 →」按钮将显示，可进入第四步。

---

## 第四步：执行部署

依次执行：更新代码 → 生成 ENV → 数据迁移 → 构建前端 → 生产启动。

### 子步骤说明

| 步骤 | 说明 |
|------|------|
| 1. 更新代码 | git pull 拉取最新代码。可选「只更新项目」（默认，不重启面板）或「含面板一起更新」（需重启面板） |
| 2. 生成 ENV | 根据配置写入 riveredge-backend/.env |
| 3. 数据迁移 | 执行 aerich upgrade 创建/更新表结构 |
| 4. 构建前端/H5 | 构建 Web 前端和手机端，若仓库已有 dist 可跳过 |
| 5. 生产启动 | 启动后端与 Caddy 反向代理 |

### 快捷操作

- **直接启动**：若 1–4 已做过，仅启动服务
- **完整启动**：执行完整流程（拉取、构建、启动）

### 代码更新提示

若执行了「更新代码」但未完成 2、3、4，会显示提示：请重做步骤 2、3、4（生成 ENV、数据迁移、构建）。

### 实时日志

执行构建或启动时，下方会显示实时日志，便于排查问题。

---

## 第五步：完成

部署完成后，可访问生产环境。

### 访问链接

页面会显示生产环境访问地址（根据配置的域名或端口）。

### 重启服务

部署完成后，可单独重启各服务使更新生效：
- **重启后端**：更新后端代码后使用
- **重启前端 Web**：更新 Web 前端后使用
- **重启手机端**：更新手机端后使用
- **一键重启**：重启后端、Caddy 等生产服务

### 启动状态

- 展示多项状态：后端 API、前端 Web、手机端、Caddy、PostgreSQL、项目构建等
- 点击「刷新」按钮检测各项，不自动刷新以减轻服务器负担
- 支持自动刷新（默认开启）
- 运行中的服务可点击「访问 →」直接打开

### 排查步骤

若页面无法访问，可展开「页面无法访问？排查步骤」查看：
1. 确认 dist 存在
2. 检查端口
3. 防火墙设置
4. 查看 Caddy 日志

### 运行日志

可选择后端、前端、Caddy、手机端查看运行日志。

### 生产停止

点击「生产停止」可停止生产服务。

## 常见问题

### Master 密码

首次使用需设置 Master 密码（至少 6 位），后续访问面板需输入。密码存储在 `panel-auth.json`。

### 端口暴露

生产环境仅需对外放通 Caddy 端口 8080（或域名 HTTPS 时 80/443）。后端绑定 127.0.0.1，无需对外暴露。

### 配置存储

- `deploy-config.json`：检测结果与用户配置
- `riveredge-backend/.env`：由「生成 ENV」根据配置写入

### Windows 说明

Windows 下运行 `Launch.prod.sh` 等 Bash 脚本时，需本机已具备可用的 `bash`（如 Git for Windows、WSL 等）。面板的 Windows 与 Linux 版本功能一致，环境检测与安装命令会按平台自动适配。
