# RiverEdge 部署面板使用指南

部署面板用于在空白 Windows/Linux 环境下图形化准备 RiverEdge 部署所需的环境（Node、Python、PostgreSQL 等），并完成配置与一键启动。单二进制、零运行时依赖，双击运行后访问 `http://127.0.0.1:8300` 即可使用。

---

## 前置准备

### 项目目录结构

将编译好的面板二进制放入 RiverEdge 项目目录：

```
riveredge/
├── riveredge-panel/
│   ├── riveredge-panel-linux-amd64   # 仓库中仅提供 Linux 二进制
│   ├── start-panel.sh
│   └── scripts/
│       └── Launch.prod.sh
├── riveredge-backend/
├── riveredge-frontend/
└── Launch.dev.sh
```

`riveredge-mobile` 已不在主仓库中维护；若需本地开发，可单独克隆或放置该工程。

### 首次运行

1. **Linux**：`./riveredge-panel/riveredge-panel-linux-amd64` 或 `sudo ./riveredge-panel/riveredge-panel-linux-amd64`（使用一键安装时建议 sudo）；亦可用 `./riveredge-panel/start-panel.sh` 启动
2. **Windows**：官方仓库不附带 Windows 面板可执行文件；本地开发请从 `panel-source` 自行 `go build`，或使用 WSL 运行上述 Linux 二进制/脚本
3. 浏览器访问 http://127.0.0.1:8300
4. 首次使用需设置 Master 密码，后续访问需输入此密码

## 第一步：环境检测

检测您的电脑是否已安装运行 RiverEdge 所需的软件。

### 检测项说明

| 组件 | 说明 | 必需 |
|------|------|------|
| Node.js 22+ | 前端运行环境 | 必需 |
| Python 3.12 | 后端运行环境 | 必需 |
| UV | Python 包管理 | 必需 |
| npm | 前端包管理 | 必需 |
| PostgreSQL 15+ | 数据库 | 必需 |
| Caddy | 生产反向代理 | 建议 |

### 操作说明

- **全部通过**：点击「全部通过，填写配置 →」进入第三步
- **有未安装项**：点击「有未安装项，去安装 →」进入第二步
- **重新检测**：安装完成后点击「重新检测」刷新状态

---

## 第二步：安装缺失组件

根据检测结果，安装未满足的组件。

### Windows

复制下方命令，在 **以管理员身份运行** 的终端中执行：
- 右键「开始」→ Windows Terminal（管理员）或 CMD（管理员）

### Linux / Ubuntu

- **Ubuntu 22/24**：支持「一键安装」，可直接点击按钮安装
- 其他发行版：复制命令到终端执行

### Ubuntu 22 测试提示

面板已在 **Ubuntu 22.04** 上完整测试，推荐作为生产部署环境：

- **一键安装**：支持 Node.js、Python、UV、PostgreSQL、Caddy 等组件的一键安装
- **sudo 权限**：使用一键安装时需 `sudo`，建议以 `sudo ./riveredge-panel` 运行面板，否则安装时可能提示输入密码
- **国内镜像**：国外源（astral.sh、cloudsmith、GitHub）访问较慢时，可勾选「使用国内镜像」加速安装
- **生产脚本**：`riveredge-panel/scripts/Launch.prod.sh` 针对 Ubuntu 22.04 优化，4GB 内存环境可运行

### 安装完成后

点击「已安装完成，去配置 →」进入第三步。若所有组件已安装，可直接点击顶部进度条「填写配置」跳转。

---

## 第三步：填写配置

填写数据库等连接信息。

### 部署方式

- **本机数据库**：数据库安装在本机，主机填 `localhost`
- **远程数据库**：使用云 RDS 等，填写实例地址

选择「远程数据库」时，会显示安全组提醒：生产环境仅需对外放通 Caddy 端口 8080（或 80/443）。

### 数据库配置

- 主机、端口（默认 5432）、用户、密码、数据库名
- 点击「测试连通性」验证连接
- 数据库不存在时会自动创建

### 应用配置

- 平台超级管理员密码（首次登录用）
- Git 仓库地址、部署分支
- Node 构建内存（MB）

### Caddy 反向代理（生产环境）

- 域名（可选，留空则用 localhost）
- 监听端口（默认 8080）
- 启用 Let's Encrypt 自动 HTTPS（需填写域名且 80 端口可从公网访问）

### 云服务器 PostgreSQL 操作提示

若使用远程数据库，可展开查看在云服务器上设置 postgres 密码、开启远程访问的命令。

### 保存配置

点击「保存配置」后，「去部署 →」按钮将显示，可进入第四步。

---

## 第四步：执行部署

依次执行：更新代码 → 生成 ENV → 数据迁移 → 构建前端 → 生产启动。

### 子步骤说明

| 步骤 | 说明 |
|------|------|
| 1. 更新代码 | git pull 拉取最新代码。可选「只更新项目」（默认，不重启面板）或「含面板一起更新」（需重启面板） |
| 2. 生成 ENV | 根据配置写入 riveredge-backend/.env |
| 3. 数据迁移 | 执行 aerich upgrade 创建/更新表结构 |
| 4. 构建 Web | 使用仓库内 `riveredge-frontend/dist`（在开发机用 `./build-web.sh` 生成并推送 dist）；服务器默认不在线编译 |
| 5. 生产启动 | 启动后端与 Caddy 反向代理 |

### 快捷操作

- **直接启动**：若 1–4 已做过，仅启动服务
- **完整启动**：执行完整流程（拉取、构建、启动）

### 代码更新提示

若执行了「更新代码」但未完成 2、3、4，会显示提示：请重做步骤 2、3、4（生成 ENV、数据迁移、构建）。

### 实时日志

执行构建或启动时，下方会显示实时日志，便于排查问题。

---

## 第五步：完成

部署完成后，可访问生产环境。

### 访问链接

页面会显示生产环境访问地址（根据配置的域名或端口）。

### 重启服务

部署完成后，可单独重启各服务使更新生效：
- **重启前端**：Caddy reload / 刷新 Web 静态（生产环境由 Caddy 托管）
- **重启后端**：更新后端代码后使用
- **重启 Caddy**：完整重启反向代理进程
- **重启 PostgreSQL**：本机数据库适用（Linux systemd；远程 RDS 请在云平台操作）
- **一键重启**：后端与 Caddy 全部重启

### 启动状态

- 展示状态：后端 API、前端 Web、Caddy、PostgreSQL（不再包含手机端 / dist 检测）
- 点击「刷新」按钮检测各项，不自动刷新以减轻服务器负担
- 支持自动刷新（默认开启）
- 运行中的服务可点击「访问 →」直接打开

### 排查步骤

若页面无法访问，可展开「页面无法访问？排查步骤」查看：
1. 确认 dist 存在
2. 检查端口
3. 防火墙设置
4. 查看 Caddy 日志

### 运行日志

可选择后端、前端、Caddy 查看运行日志；生产环境下「前端」与「Caddy」对应同一 `caddy.log`（无单独 Vite 进程）。

### 生产停止

点击「生产停止」可停止生产服务。

## 本地与生产同步（避免「本地功能全、远程旧」）

生产服务器**默认不在机器上执行 `npm run build`**，只使用 Git 里已提交的 `riveredge-frontend/dist`（见 `riveredge-panel/scripts/Launch.prod.sh` 的 `do_build`）。因此常见落后原因如下。

| 环节 | 说明 |
|------|------|
| 前端未进仓 | 本地只跑 `npm run dev`，没有构建并提交 `riveredge-frontend/dist`，生产拉到的仍是旧静态资源。 |
| 未 push / 未拉取 | 构建后未 `git push`，或生产未在面板执行「拉取代码」「更新生产」。 |
| 只更前端、忘了后端 | `dist` 已更新，但 `riveredge-backend` 的提交未推送，或生产未跑迁移/重启，会出现「界面新、接口旧」或报错。 |
| 分支不一致 | 本地在 `develop` 开发，生产 `deploy-config` 里 `git_branch` 指向其他分支。 |

**推荐做法**

1. 在开发机执行项目根目录的 **`./build-web.sh`**：先构建 Web，再提交并推送 **`riveredge-frontend/dist` 以及当前仓库内其它已跟踪的修改**（如后端、`riveredge-panel`、文档等）；若仅有 dist 以外的改动而 dist 未变，仍会提交。脚本要求分支已跟踪 `origin`、且本地**不落后**于远程（否则先 `git pull`）。
2. 后端有变更时，单独 `commit` / `push` `riveredge-backend`，并在生产通过面板的「数据迁移」或「更新生产」使代码与数据库结构一致。
3. 发布后在服务器面板使用 **「更新生产」**（或 `git pull` + 构建步骤 + 重启），确保新 `dist` 与后端已部署。

## 常见问题

### Master 密码

首次使用需设置 Master 密码（至少 6 位），后续访问面板需输入。密码存储在 `panel-auth.json`。

### 端口暴露

生产环境仅需对外放通 Caddy 端口 8080（或域名 HTTPS 时 80/443）。后端绑定 127.0.0.1，无需对外暴露。

### 配置存储

- `deploy-config.json`：检测结果与用户配置
- `riveredge-backend/.env`：由「生成 ENV」根据配置写入

### Windows 说明

生产启动脚本为 Bash，路径为 `riveredge-panel/scripts/Launch.prod.sh`。在 Windows 上需通过 WSL 或 Git Bash 等环境执行；若项目根下存在可选的 `riveredge-panel/Launch.prod.win.sh`，面板会优先调用。环境检测与安装命令仍按平台自动适配。
