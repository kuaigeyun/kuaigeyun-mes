# 审厂证据：物料先进先出（FIFO）

面向客户/二方审厂时，用现网能力组装「策略 + 执行 + 单据证据」，无需单独「FIFO 合格证」。

## 1. 策略层（证明公司规定 FIFO）

1. 打开 **配置中心 → 流程/参数中的仓储相关项**。
2. 确认：
   - `批次管理`（`parameters.warehouse.batch_management`）开启
   - `先进先出`（`parameters.warehouse.fifo`）开启
   - `先进先出判定方式`（`parameters.warehouse.fifo_mode`，可选）：
     - `batch_id`：按批次建档顺序（默认，与历史行为一致）
     - `production_date`：按生产日期（早生产先出）
     - `expiry_date`：按有效期（先到期先出，FEFO）
3. 截图保存为证据。

物料主数据：抽样物料勾选 **批次管理**，导出或截图清单。

## 2. 执行层演示（证明系统会拦截越批）

准备同一物料、同一仓库下至少两个在库批次（建议填写生产日期/有效期）。

1. 故意用「较新」批次做领料/出库确认。
2. 系统应提示类似：`【防呆拦截】当前物料不符合先入先出…`
3. 改用「建议优先」批次后确认成功。

录像或截图拦截页 + 成功单据，作为执行证据。

## 3. 单据与台账证据

| 证据 | 建议入口 |
|---|---|
| 出库/领料单含批号 | 仓储出库、生产领料详情/打印 |
| 库存流水 | 库存流水 / 收发存，按物料+批号筛选 |
| 批次库存 | 仓储 → 批次库存查询 |
| 质量追溯 PDF | 质量管理 → 追溯，按批号生成 |
| FIFO 例外抽查 | 仓储报表 → FIFO 例外抽查（导出） |

## 4. 对客户说明（边界）

- 开启 FIFO 后，指定批号出库时会硬拦截「仍有更应先出的在库批」。
- 判定键以组织配置的 `fifo_mode` 为准；默认 `batch_id` 近似入库先后，不等于未配置生产日期时的 FEFO。
- 入库尽量维护 **生产日期 / 有效期**，证据更贴近客户条款。

- [ ] 配置截图（FIFO + 批次 + 判定方式）
- [ ] 批次管理物料清单
- [ ] 双批次库存样例（含日期字段）
- [ ] 越批拦截演示
- [ ] 成功出库/领料单（含批号）
- [ ] 库存流水导出
- [ ] 追溯 PDF（如需要）
