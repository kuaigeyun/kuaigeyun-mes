# RiverEdge 部署指南

本文档说明如何在 **Linux** 与 **Windows** 上部署 RiverEdge（快格云制造）。推荐统一使用 [`fast-deploy`](../fast-deploy/deploy.sh) 对话式向导；Windows / Linux 均已在生产模式与开发模式下完成验证。

## 环境要求

| 组件 | 版本 | 开发 | 生产 | 说明 |
|------|------|:----:|:----:|------|
| Node.js | 22+ | 必需 | 必需 | 生产模式用于构建前端 |
| Python | 3.12+（检测/安装） | 必需 | 必需 | 应用虚拟环境由 `uv` 按 `pyproject.toml` 锁定 **3.11** |
| uv | 最新 | 必需 | 必需 | Python 依赖与虚拟环境 |
| npm | 10+ | 必需 | 必需 | 随 Node.js 安装 |
| PostgreSQL | 15+ | 必需 | 必需 | 本地安装或远程库 |
| Caddy | 最新 | — | 必需 | 生产模式反向代理与静态资源 |

**不需要 Redis。** 异步任务由 **Taskiq + PostgreSQL** 承担；缓存与在线状态亦可在 PG 侧完成。

### 硬件建议

| 场景 | CPU | 内存 | 磁盘 |
|------|-----|------|------|
| 开发 / 试用 | 2 核+ | 4 GB+ | 20 GB+ |
| 生产（中小团队） | 4 核+ | 8 GB+ | 50 GB+（含数据库与日志） |

## 快速开始

```bash
git clone https://gitee.com/kuaigeyun/kuaigeyun.git
cd kuaigeyun   # 或你的仓库目录名 riveredge

# 生产模式（推荐首次部署）
./fast-deploy/deploy.sh

# 开发模式（Vite 热重载 + 后端 reload）
./fast-deploy/deploy.sh dev
```

向导第一步可选：**全新安装** / **修改配置** / **更新系统**。

安装完成后典型访问地址：

| 模式 | Web | API |
|------|-----|-----|
| 生产 | `http://<服务器IP>:8080` | `http://<服务器IP>:8080/api` |
| 开发 | `http://<服务器IP>:8100` | `http://<服务器IP>:8200` |

## 部署成功后的常见操作

向导阶段 8 会输出 Web 地址与平台超管用户名。以下步骤适用于**首次部署完成**后的初始化。

### 1. 确认服务可访问

```bash
./fast-deploy/deploy.sh status
```

浏览器打开向导给出的 Web 地址（生产一般为 `http://<服务器IP>:8080`）。若无法访问，请先核对防火墙是否放行对应端口，并参考 [故障排查](#故障排查)。

### 2. 登录平台超管

平台超管用于**多组织（租户）运维**，与组织内业务账号相互独立。

| 项目 | 说明 |
|------|------|
| 登录地址 | `http://<服务器IP>:8080/infra/login`（开发模式将端口改为 `8100`） |
| 用户名 | `riveredge-backend/.env` 中的 `PLATFORM_SUPERADMIN_USERNAME`（向导未指定时默认为 `infra_admin`） |
| 密码 | 同文件中的 `PLATFORM_SUPERADMIN_PASSWORD`（向导阶段 2 填写；请妥善保管） |

登录成功后进入**平台运营看板**（`/infra/operation`）。左侧菜单可进入组织管理、套餐配置、平台设置等。

> **说明**：请勿将平台超管账号当作日常业务账号使用。组织内的管理员与业务用户应在下方步骤创建的组织中登录。

### 3. 创建第一个组织（租户）

1. 在平台侧栏进入 **组织管理**（`/infra/tenants`）。
2. 点击 **新建**，填写基本信息：
   - **组织名称**：如「示例制造有限公司」
   - **组织域名（domain）**：仅小写字母、数字、连字符，如 `demo-factory`（组织用户登录时用于检索/识别组织）
   - **状态**：首次自用建议选 **激活**
   - **套餐类型**：试用 / 基础 / 专业 / 企业（会联动默认用户数与存储配额，可再调整）
3. 在同一表单中填写 **组织管理员** 账号（用户名、密码等）。保存后系统会创建该组织及其首位管理员。
4. 若组织状态为「未激活」，可在列表中对应用 **激活** 或 **审核通过**。

通过登录页 **自助注册** 的组织，默认需平台审核（可在 **平台管理 → 平台设置** 中开启「自动审核」）。**平台超管手动新建**且状态为「激活」的组织，无需额外审核即可使用。

### 4. 组织管理员登录业务系统

| 项目 | 说明 |
|------|------|
| 登录地址 | `http://<服务器IP>:8080/login`（开发模式端口 `8100`） |
| 组织 | 在登录页搜索或选择刚创建的 **组织域名** 或组织名称 |
| 账号 | 步骤 3 中填写的组织管理员用户名与密码 |

登录后进入该组织的系统工作台（如 `/system/dashboard/workplace`）。后续可在 **系统管理 → 用户管理** 中创建更多用户，在 **应用中心** 安装快格轻制造等业务应用。

### 5. 其他常见后续操作

| 操作 | 入口 / 命令 |
|------|-------------|
| 修改平台超管或数据库配置 | `./fast-deploy/deploy.sh configure`，或直接编辑 `riveredge-backend/.env` 后重启 |
| 查看运行日志 | `.logs/backend.log`、`.logs/caddy.log` 等（见 [故障排查](#故障排查)） |
| 升级版本 | 先备份 → `./fast-deploy/deploy.sh update` |
| 修改访问 IP 或端口 | 编辑 `fast-deploy/config/deploy.env`，再执行 `configure` 或按向导 **修改配置** |

## 向导流程

### 入口三选一

| 选项 | 说明 |
|:----:|------|
| **1) 全新安装** | 8 阶段完整流程 |
| **2) 修改配置** | 调整数据库、超管、访问 IP 等 |
| **3) 更新系统** | 拉代码 → 迁移 → 构建（生产）→ 重启 |

### 全新安装（8 阶段）

| 阶段 | 名称 | 说明 |
|:----:|------|------|
| 1 | 系统识别 | Windows / Linux、部署模式、镜像策略 |
| 2 | 安装规划 | 数据库、超管、服务器 IP（可复用已有 `.env`） |
| 3 | 环境监测 | Node / Python / uv / npm / PostgreSQL / Caddy |
| 4 | 环境准备 | 目录、deploy.env、国内镜像 |
| 5 | 环境软件安装 | 自动安装缺失组件 |
| 6 | 应用配置 | JWT、BASE_URL、CORS、数据库连通性 |
| 7 | 系统安装 | 迁移 → 构建 → 启动 |
| 8 | 安装完成 | 展示访问地址与常用命令 |

阶段 2 若检测到 `riveredge-backend/.env` 已有完整配置，可选择 **使用已有配置** 或 **重新填写**；服务器 IP 可选择 **使用检测值** 或 **手动输入**。

## 部署模式与端口

| 变量 / 配置 | 默认 | 说明 |
|-------------|------|------|
| `PROXY_PORT` | 8080 | 生产 Web 入口（Caddy） |
| `BACKEND_PORT` | 8200 | 后端 API（开发直连；生产经 Caddy `/api`） |
| `FRONTEND_PORT` | 8100 | 开发 Vite 端口 |

生产架构：

```
浏览器 → Caddy :8080 → 静态 dist（前端）
                    └→ /api → uvicorn :8200（后端）
Taskiq Worker / Scheduler → PostgreSQL
```

## 子命令参考

```bash
./fast-deploy/deploy.sh              # 向导（同 wizard）
./fast-deploy/deploy.sh dev          # 开发模式向导
./fast-deploy/deploy.sh check        # 环境检测
./fast-deploy/deploy.sh install      # 仅安装系统依赖
./fast-deploy/deploy.sh configure    # 配置向导
./fast-deploy/deploy.sh migrate      # uv sync + aerich upgrade
./fast-deploy/deploy.sh build        # 构建前端 dist
./fast-deploy/deploy.sh start        # 启动服务
./fast-deploy/deploy.sh stop         # 停止
./fast-deploy/deploy.sh status       # 状态
./fast-deploy/deploy.sh update       # 拉代码 + 迁移 + 重启
```

### 环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `USE_MIRROR=1` | 启用 | 国内镜像（uv / npm / PG 源等） |
| `USE_MIRROR=0` | — | 禁用镜像，全走官方源 |
| `DEPLOY_MODE=prod\|dev` | prod | 部署模式 |
| `WIZARD_TYPING=0` | — | 关闭向导逐行延迟 |

## Windows 说明

### 推荐方式

在 **Git Bash** 中运行（与 Linux 同一套脚本）：

```bash
./fast-deploy/deploy.sh
```

- 系统依赖安装会自动调用 PowerShell（`fast-deploy/windows/install-component.ps1`）
- **winget 不可用时** 会自动 fallback：Node MSI / Python 安装包 / PostgreSQL EDB 安装包 / Caddy 便携版
- 安装后脚本会自动补充 PATH（含便携版 `.tools/node`）

### 其他入口

| 方式 | 命令 |
|------|------|
| PowerShell | `.\fast-deploy\windows\prod.ps1` / `dev.ps1` |
| 双击 | `fast-deploy\windows\dev.cmd` |

### Windows 特别注意

1. **首次安装 PostgreSQL** 建议使用**管理员身份**打开 Git Bash（EDB 安装包需要权限）
2. **防火墙**：生产模式需放行 **8080**（及开发模式 8100/8200）
3. **Caddy 静态路径**：脚本已将 Git Bash 路径转为 `C:/...`，避免 8080 返回 404
4. **pyzbar**：若缺少 DLL，后端仍可启动，仅「从图片解析二维码」不可用；`migrate` 时会尝试重装 Windows 版 pyzbar
5. **UTF-8**：迁移阶段已设置 `PYTHONUTF8=1`，避免 aerich 读取中文注释的 `pyproject.toml` 失败

## Linux 说明

在 Ubuntu 22.04 / 24.04 等 Debian 系发行版上验证通过。

```bash
./fast-deploy/deploy.sh
```

- PostgreSQL 15 走 PGDG 源（`USE_MIRROR=1` 时使用阿里云镜像）
- Caddy 走 apt 安装；脚本会自动 **stop + disable** 系统 `caddy.service`，避免与项目 Caddyfile 冲突
- **zbar / libzbar0**：`install` / 向导依赖安装 / `migrate`（`uv sync` 后）会自动安装，供 `pyzbar` 解析发票 PDF 二维码；也可手动：`sudo apt-get install -y libzbar0`（RHEL/Fedora：`sudo dnf install -y zbar`）
- 若 `<1024` 端口绑定失败，按提示执行 `sudo setcap 'cap_net_bind_service=+ep' $(which caddy)`

也可使用快捷脚本：

```bash
./fast-deploy/linux/prod.sh
./fast-deploy/linux/dev.sh
```

## 配置说明

### 文件位置

| 文件 | 说明 |
|------|------|
| `riveredge-backend/.env` | 应用配置（数据库、JWT、超管等） |
| `fast-deploy/config/deploy.env` | 部署配置（端口、SERVER_IP、Caddy 域名、`TASKIQ_WORKERS` 等） |
| `fast-deploy/caddy/Caddyfile` | 生产 Caddy（自动生成） |
| `fast-deploy/config/install-scripts.json` | 各平台安装命令定义 |
| `.logs/*.log` | 运行日志 |

### 数据库

向导阶段 2 支持：

- **本地 PostgreSQL**：脚本安装并初始化库、用户、密码
- **远程数据库**：跳过本地 PG 安装，仅写入连接信息

`.env` 关键项：`DB_TARGET`、`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`。

连接池（多进程叠加，小内存机建议调小）见 `riveredge-backend/.env.example` 中的 `RIVEREDGE_DB_POOL_*`、`RIVEREDGE_TASKIQ_POOL_*`。

### Taskiq 内存

`deploy.env` 中 `TASKIQ_WORKERS` 控制异步 worker **子进程数**（Taskiq CLI 默认为 2，每个子进程约占用 200MB+）。生产环境建议 `TASKIQ_WORKERS=1`；队列积压时可酌情调大。修改后需 `restart-worker`。

### 应用 API 路由

应用级 API（`/api/v1/apps/<code>/…`）在启动时**仅加载**数据库 `core_applications` 中「已安装且启用」的应用，不再在 `main.py` 静态 import 全部应用，也不再自动合并磁盘上未入库的 router。未安装的应用请在**应用中心**安装/启用后重启后端；异步事件处理器在 **Taskiq Worker** 中按同样规则加载。

### 超管账号

写入 `.env` 的 `PLATFORM_SUPERADMIN_USERNAME` / `PLATFORM_SUPERADMIN_PASSWORD`，首次登录使用。

## 日常运维

### 备份（升级前必做）

<div style="padding:12px 16px;margin:12px 0 16px;background-color:#fff2f0;border:1px solid #ffccc7;border-left:4px solid #ff4d4f;border-radius:4px;color:#434343;">
<strong style="color:#cf1322;">⛔ 操作前提醒</strong><br/>
<strong>测试环境</strong>亦建议建立定期备份机制；<strong>生产环境或已存有业务数据的实例</strong>，在每次执行 <code>update</code>、数据库迁移或拉取含 schema 变更的版本前，<strong style="color:#cf1322;">须先完成备份</strong>。
</div>

```bash
# 示例：逻辑备份（请按实际 DB 用户/库名替换）
pg_dump -h 127.0.0.1 -U riveredge -Fc -f "riveredge-backup-$(date +%Y%m%d-%H%M).dump" riveredge

# 同步备份配置（路径以你的安装目录为准）
cp riveredge-backend/.env "riveredge-backend/.env.bak-$(date +%Y%m%d)"
cp fast-deploy/config/deploy.env "fast-deploy/config/deploy.env.bak-$(date +%Y%m%d)"
```

将 `.dump` 与配置文件副本保存到**与服务器分离**的存储（对象存储、NAS 或运维机），并定期演练还原。

```bash
# 查看状态
./fast-deploy/deploy.sh status

# 更新版本（拉代码、迁移、生产模式会 rebuild）
./fast-deploy/deploy.sh update

# 仅重启
./fast-deploy/deploy.sh stop
./fast-deploy/deploy.sh start

# 修改配置后
./fast-deploy/deploy.sh configure
```

生产环境更新前端：

```bash
./fast-deploy/deploy.sh build
./fast-deploy/deploy.sh stop
./fast-deploy/deploy.sh start
```

## 故障排查

| 现象 | 处理 |
|------|------|
| `install` 后 `check` 仍失败 | 关闭并重新打开终端；或再执行 `./fast-deploy/deploy.sh check` |
| 数据库连接失败 | 核对 `DB_PORT`（Windows 默认 5432）、密码、PostgreSQL 服务是否运行 |
| **8080 无法访问 / HTTP 404** | 确认已 `build` 且存在 `riveredge-frontend/dist/index.html`；查看 `.logs/caddy.log`；Windows 需拉取含 Caddy 路径修复的最新脚本 |
| 后端启动超时 | 查看 `.logs/backend.log`；常见为 pyzbar DLL（已降级，不应阻断启动）或数据库未就绪 |
| 迁移 `UnicodeDecodeError` | 确保使用最新 `fast-deploy`（已设置 `PYTHONUTF8=1`） |
| Node/Python 已装仍显示未安装 | Windows 下执行 `git pull` 获取 PATH 探测修复；或重开 Git Bash |
| Linux Caddy 端口冲突 | `sudo systemctl stop caddy && sudo systemctl disable caddy` |

### 日志路径

| 日志 | 路径 |
|------|------|
| 后端 | `.logs/backend.log` |
| Caddy | `.logs/caddy.log` |
| Worker | `.logs/worker.log` |
| 向导依赖安装 | `.logs/wizard-deps.log` |
| 向导部署 | `.logs/wizard-deploy.log` |
