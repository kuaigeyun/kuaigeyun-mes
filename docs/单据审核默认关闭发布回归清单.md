## 发布前检查
- 确认已部署包含迁移脚本 `189_20260422130000_default_no_audit_promote_pending_to_confirmed.py` 的后端版本。
- 确认流程设置中各单据审批流程默认 `is_active=false`。
- 备份生产库（至少备份以下表）：

  - `apps_kuaizhizao_purchase_requisitions`
  - `apps_kuaizhizao_production_plans`
  - `apps_kuaizhizao_incoming_inspections`
  - `apps_kuaizhizao_process_inspections`
  - `apps_kuaizhizao_finished_goods_inspections`

## 发布顺序
1. 发布后端代码。
2. 执行数据库迁移（包含 189 脚本）。
3. 重启后端进程（确保新逻辑生效）。
4. 发布前端代码。
5. 强刷前端缓存后开始业务验收。

## 数据迁移验收 SQL（示例）
- 待审核剩余量应显著下降：
```sql
SELECT 'sales_orders' AS table_name, count(*) AS pending_count
FROM apps_kuaizhizao_sales_orders
WHERE COALESCE(review_status, '') IN ('PENDING', '待审核', 'PENDING_REVIEW')
UNION ALL
SELECT 'purchase_orders', count(*)
FROM apps_kuaizhizao_purchase_orders
WHERE COALESCE(review_status, '') IN ('PENDING', '待审核', 'PENDING_REVIEW')
UNION ALL
SELECT 'demands', count(*)
FROM apps_kuaizhizao_demands
WHERE COALESCE(review_status, '') IN ('PENDING', '待审核', 'PENDING_REVIEW');
```

- 已确认量应上升（示例）：
```sql
SELECT 'sales_orders' AS table_name, count(*) AS confirmed_count
FROM apps_kuaizhizao_sales_orders
WHERE status IN ('CONFIRMED', '已确认')
UNION ALL
SELECT 'purchase_orders', count(*)
FROM apps_kuaizhizao_purchase_orders
WHERE status IN ('CONFIRMED', '已确认')
UNION ALL
SELECT 'demands', count(*)
FROM apps_kuaizhizao_demands
WHERE status IN ('CONFIRMED', '已确认');
```

## 功能回归要点
- 流程关闭时：
  - 新建并提交销售订单/采购订单/销售预测/需求后，状态直接进入已确认，审核状态为已通过。
  - 列表页“待审核”筛选项无新增数据。
- 流程开启时（在流程设置中单独开启某单据）：
  - 新单提交后进入待审核。
  - 审核通过后进入已审核/已确认链路。
- 看板与报表：
  - 运营看板销售/采购聚合不再因“待审核积压”导致偏差。
  - 销售报表执行中口径可覆盖已确认和已审核存量数据。

## 回滚建议
- 若出现异常，优先回滚应用版本并恢复数据库备份。
- 若仅个别表状态迁移异常，可按备份表或审计日志做定向回滚，不建议手工全库批改。
